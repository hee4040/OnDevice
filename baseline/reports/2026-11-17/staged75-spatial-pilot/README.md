# `staged_75` 공간 분포 토큰 선택 예비 실험

실행일: 2026-11-17 · 장치: Colab Tesla T4 · 데이터: ImageNet-1K validation 5,000장

## 한눈에 보는 결과

기존 `staged_75`의 CLS attention Top-K 선택에 **4×4 공간 분포 조건**을 추가했다. 같은 이미지, 모델, 라우팅, 토큰 수에서 공간 분포 방식의 Top-1은 **80.92%**, 기존 방식은 **80.96%**였다. 차이는 **−0.04%p(5,000장 중 정답 2개 감소)**로, 이 표본에서는 성능 개선을 확인하지 못했다.

| 항목 | 기존 Top-K | 공간 분포 Top-K |
| --- | ---: | ---: |
| 전체 Top-1 | 80.96% (4,048/5,000) | 80.92% (4,046/5,000) |
| 6H로 라우팅된 이미지 | 1,747/5,000 (34.94%) | 동일 |
| 6H의 해석적 연산량 | 4.0175 GMACs | 동일 |

같은 이미지에서 새 방식만 맞힌 경우는 4장, 기존 방식만 맞힌 경우는 6장이다. 이미지별 정오 차이에 대한 정규근사 95% 구간은 **[−0.164, +0.084]%p**다. 이 구간은 탐색적·기술적 요약이며, 별도의 미사용 검증 집합에서 확인한 효과를 뜻하지 않는다.

## 실험 질문과 설계

질문은 “이미 정한 레이어별 제거 시점과 토큰 수를 유지하면서, 선택된 토큰의 공간 분포를 보장하면 정확도가 오르는가?”이다. 기존 [Layer-wise Drop 본실험](../../2026-11-08/layerwise-drop/README.md)의 `staged_75`를 기준으로 했다.

ThinkingViT의 3H 마지막 Block에서 얻은 head 평균 CLS attention으로 196개 패치의 중요도를 정한다. 엔트로피가 **τ=1.0 이상**인 이미지만 6H에 보내고, 6H의 각 Block 진입 전에 패치 토큰을 실제로 제거한다. CLS 토큰은 항상 유지하며 제거된 토큰은 복원하지 않는다.

| 6H Block | 1–4 | 5–8 | 9–12 |
| --- | ---: | ---: | ---: |
| 유지 패치 | 196 | 172 | 147 |
| CLS 포함 토큰 | 197 | 173 | 148 |

- **기존 방식:** 3H CLS attention 점수가 높은 패치를 전역 Top-K로 선택한다.
- **공간 분포 방식:** 14×14 패치 격자를 4×4 구역으로 나누고, 각 구역에서 attention 상위 6개씩 총 96개 패치를 우선 선택한다. 나머지 자리는 전역 attention 순위로 채운다. 패치 순위는 한 번 정하며 각 Block의 토큰 수는 기존 방식과 같다.

공식 EMA 가중치와 공식 ThinkingViT 소스(`9254c4950d3159937ad682592d58a2be69708c42`)를 사용했다. 평가에 사용한 OnDevice 소스는 `8bd600696223b7863302b243467b754c4246274c`이다. 학습이나 파인튜닝은 하지 않았다. PyTorch 2.5.1+cu124, float32 및 TF32 허용, 배치 32, DataLoader worker 2였다. `ImageFolder`가 읽은 검증 집합 50,000장 중 `torch.randperm` seed 42로 5,000장을 뽑아 두 방식을 **같은 순서로** 평가했다. 기존 Drive의 이미지를 직접 읽었고 전체 검증 이미지를 Colab 디스크에 다시 복사하지 않았다.

## 토큰 선택 변화와 해석

6H로 라우팅된 1,747장 중 **1,502장**에서 최종 147개 패치 집합이 바뀌었다. 바뀐 패치 수는 라우팅 이미지당 평균 **2.74개**였다. 따라서 정확도 차이가 거의 없었던 이유를 “두 정책이 늘 같은 토큰을 고른다”고 해석할 수는 없다. 다만 최종 토큰의 약 2개에서 3개만 교체되는 비교여서 효과의 크기도 제한될 수 있다.

두 방식의 Block별 토큰 수와 라우팅 결정이 같으므로, 기존 MAC 계산식으로 산출한 6H 연산량은 모두 **4.017509376 GMACs**다. 이 값에는 공간 구역 선정, 정렬, gather, 분기 등의 비용이 포함되지 않는다. 이 실험에서는 GPU 추론 지연 시간을 따로 재지 않았으므로 실제 속도가 같다고 결론 내릴 수 없다. 셀 실행 시간에는 Drive 이미지 읽기와 초기 목록 탐색이 포함되어 추론 지연 시간으로 사용할 수 없다.

기존 50,000장 본실험의 `staged_75` Top-1 **80.212%**와 여기의 **80.96%**는 표본 크기가 다른 수치다. 새 정책의 효과는 이 예비 실험 안에서 **80.96% 대 80.92%의 짝지은 비교**로 읽어야 한다.

## 결론과 한계

이 5,000장 표본에서는 공간 분포 조건을 추가해도 정확도 개선이 관찰되지 않았다. 차이는 −0.04%p이고 기술적 95% 구간에는 0이 포함된다. 선택 규칙을 같은 validation 데이터에 대한 이전 결과를 본 뒤 정했으므로 독립적인 최종 검증 결과로 제시하지 않는다. 단일 표본·단일 seed이며 실제 GPU latency도 측정하지 않았다.
